# Retro Diffusion API — context for AI agents (verified 2026-09)
Pixel art generation API: images, animations, tilesets and low-poly 3D models. Default base URL for new integrations: https://api.retrodiffusion.ai/v2
V1 remains supported with no retirement plan at https://api.retrodiffusion.ai/v1. V2 uses {"error":{"code":"...","message":"...","request_id":"..."}} for every JSON error, corrects authentication to 401 and insufficient balance to 402, and returns the same request ID in X-Request-ID. Never retry a failed paid request by falling back across versions.
Auth: send header "X-RD-Token: <key>" on every request. Keys start with "rdpk-".
Humans create keys at https://www.retrodiffusion.ai/app/devtools (max 5 per account).
Prefer MCP if available: https://mcp.retrodiffusion.ai/mcp (HTTP transport, header "Authorization: Bearer <key>").
MCP tools (33): create_inference, estimate_inference_cost (free), start_inference_job + get_inference_job (async jobs — recommended for animations and batches; success results carry hosted output_urls, not base64), list_inference_jobs, get_inference_result, list_available_styles, list_available_models, get_style_usage, list_edit_tools, run_edit_tool, estimate_edit_tool_cost (free), fix_pixel_art ($0.002 standard, $0.005 neural), create_user_style, update_user_style, delete_user_style, Low-Poly 3D: get_lowpoly_pricing, estimate_lowpoly_cost (free), start_lowpoly_generate, start_lowpoly_revise, start_lowpoly_animate (pass animation to change an existing one), start_lowpoly_split, start_lowpoly_rerig, get_lowpoly_job, get_lowpoly_model, list_lowpoly_models, export_lowpoly_model, recolor_lowpoly_model, delete_lowpoly_animation; authenticate, get_balance, get_service_status, logout. Tip: pass upload_outputs=true on create_inference to receive temporary signed URLs instead of base64 payloads.
MCP setup guides for every client (Claude Code + plugin, Cursor, VS Code, Windsurf, Claude Desktop) live at https://github.com/Retro-Diffusion/retro-diffusion-mcp.

## Generate images
POST /v2/inferences  (Content-Type: application/json)
Required fields: width (int), height (int), num_images (int; clamped to between 1 and the style's max_number_of_images, and you are charged for the clamped count). Send prompt_style to select a style. prompt defaults to an empty string and is required only when the selected style's prompt_requirement says so; image-driven styles may accept an empty prompt.
Optional fields: seed (int, reproducible), input_image (base64 PNG string, NO "data:image/png;base64," prefix, RGB without transparency) + strength (float 0-1, default 0.75 — how much to change the input), reference_images (array of base64, RD Pro styles only, up to 9, guides style/content without redrawing), input_palette (base64, constrains output colors), remove_bg (bool, transparent output), tile_x / tile_y (bool, seamless tiling), frames_duration (int 4|6|8|10|12|16, animation styles), return_spritesheet (bool, animations: PNG spritesheet instead of GIF), upscale_output_factor (int, 1 = native pixel size), bypass_prompt_expansion (bool, skip automatic LLM prompt enrichment), include_downloadable_data (bool, extra structured assets e.g. item atlas JSON), check_cost (bool, FREE dry run: returns price immediately, generates nothing, charges nothing).
The "negative" field exists but is a placeholder — current models ignore it. Do not rely on it.
Size limits: the API validates 12x12 to 512x512, but each style enforces tighter limits (current styles top out at 384x384) — use the per-style limits in the catalog below or from the selector.
Before a paid submission, persist a unique Idempotency-Key (1-256 visible ASCII characters). Reuse that key only with identical inputs when the admission response is uncertain. Once task_id is known, poll that task instead of submitting again. Do not send Idempotency-Key on check_cost requests or edit/pixel-fixer routes.

### Example: accepted response
{"status":"accepted","task_id":"8d24e990-...","request_id":"8d24e990-...","message":"Inference accepted. Poll GET /v2/inferences/tasks/{task_id} for status."}
Poll the task until it succeeds, then read task.result. Its base64_images entries are raw base64 PNG (or GIF for animation styles). Every successful generation is retained privately for 24 hours. Add "upload_outputs": true to receive 15-minute signed URLs in "output_urls". Large results are returned as hosted output_urls with base64_images empty — always handle both fields. Refresh access during retention with GET /v2/inferences/requests/{request_id}; URL expiry never extends the 24-hour deadline.

## Async jobs (the v2 generation contract)
POST /v2/inferences
-> {"status": "accepted", "task_id": "8d24e990-...", "request_id": "8d24e990-...", "message": "Inference accepted. Poll GET /v2/inferences/tasks/{task_id} for status."}
Poll GET /v2/inferences/tasks/{task_id} (same X-RD-Token) every ~2s:
-> {"status": "pending" | "running" | "succeeded" | "failed", "task_id": "...", "result": <generation response when succeeded>, "error": {"status_code": 502, "code": "inference_failed", "message": "...", "request_id": "..."} when failed}

## Retrieve a generation during the 24-hour output window
GET /v2/inferences/requests/{request_id} with X-RD-Token
-> status, safe request settings, billing result, public failure details, and freshly signed output URLs.
Any active personal key from the owning account may retrieve a request after key rotation. System-key requests require the same system key. Unknown, non-owned, and expired output objects never expose bucket names or object keys.

## Low-Poly 3D models (async; base /v2/lowpoly)
Real low-poly 3D models with pixel-art textures from a prompt (<=250 chars) and/or up to 4 reference_images (base64). size: 16|32|64|128|256|"auto" (auto reads the prompt; image-only defaults to 64). style: rd_lowpoly__detailed (default) | rd_lowpoly__blocky (boxes only) | rd_lowpoly__detailed_lite | rd_lowpoly__blocky_lite (Lite: a lighter model, simpler results, $0.10 per model at any size and $0.08 per revise/animate/split/re-rig of a Lite model; mode is ignored; GET /lowpoly/pricing lists each style's prices). mode: auto (default: quality, or fast for simple requests) | quality | fast (same price).
Prices by size 16/32/64/128/256 - generate $0.25/$0.50/$0.85/$1.20/$3.00, revise $0.20/$0.35/$0.65/$0.90/$1.50, animate $0.15/$0.25/$0.35/$0.50/$1.00, split and re-rig $0.10/$0.10/$0.15/$0.20/$0.25 each; the first animation rigs the model free; estimates, reads and exports are free; failed jobs refund automatically.
POST /lowpoly/generate {prompt?, size?, style?, mode?, reference_images?, reference_models? (asset_ids of your own finished models, placed exactly or adapted; images+models <= 4), input_palette? (palette image: the model uses only its colors; revisions/animations keep them), custom_id?} -> 202 {task_id, asset_id, cost, size}. POST /lowpoly/assets/{asset_id}/revise {prompt, version?, reference_images?} saves a new version. POST /lowpoly/assets/{asset_id}/animate {prompt, version?, animation?} adds an animation to that version; with animation set to an existing animation's name it changes that animation instead (same price, keeps its name; unknown name -> 404 lowpoly_animation_not_found). Poll GET /lowpoly/tasks/{task_id} every 10-20 s (jobs take 1-5 min, up to ~15 at 256): succeeded -> result {asset_id, versions:[{number, render_url, turntable_url, animations, stats}]}, plus animation (the added or changed one).
POST /lowpoly/assets/{asset_id}/export {target, version?, animation?} -> {url, filename}: godot|unity|unreal|web|blender (.glb), blockbench (.bbmodel), obj (zip), minecraft (resource pack), atlas, turntable, axis_views (zip of 6 PNGs seen along +X/-X/+Y/-Y/+Z/-Z: orthographic, 1 px per texel, no antialiasing, texture colors), gif|sheet|mp4 (pass animation; gif/sheet without one = every animation in one zip; mp4 = 1024px H.264 video). glb and bbmodel include the rig and every animation. GET /lowpoly/pricing, POST /lowpoly/estimate, GET /lowpoly/assets, GET /lowpoly/assets/{asset_id}, DELETE /lowpoly/assets/{asset_id}.
POST /lowpoly/assets/{asset_id}/rerig {prompt?, version?} rebuilds a rigged version's skeleton in place (prompt optional: 'give the tail three bones'); animations whose bones the new rig still has are kept; an unrigged version -> 409 lowpoly_not_rigged (its first animation rigs it free).
POST /lowpoly/assets/{asset_id}/split {prompt?, version?} breaks the model into separate models, one per object (prompt optional: 'only the books', 'each drawer too'); each piece is a new model and history item facing the front, with its own atlas, rig and animations (free); the original is unchanged; the succeeded task lists them in pieces [model, ...]; a single object -> lowpoly_split_failed (refunded).
POST /lowpoly/assets/{asset_id}/recolor {tool: color_reducer|palette_converter|color_style_transfer, version?, color_count?, dither_mode?, dither_strength?, palette_image?, reference_image?} -> the model with a new version (the image canvas's color tools on the texture atlas; reducer and converter $0.001, style transfer $0.01; later revisions and animations keep the colors).
DELETE /lowpoly/assets/{asset_id}/versions/{number}/animations/{name} -> the model: deletes one animation from that version (free); the rig stays, so animating again needs no new rig.
Example: POST /v2/lowpoly/generate {"prompt":"a cute corgi wearing sunglasses","size":"auto"} (X-RD-Token + Idempotency-Key) -> poll task -> POST /v2/lowpoly/assets/{asset_id}/animate {"prompt":"rocks out to music"} -> poll (task.animation = its name) -> POST /v2/lowpoly/assets/{asset_id}/export {"target":"godot"} and {"target":"mp4","animation":"<name>"}.
Example (reference images, blocky): POST /v2/lowpoly/generate {"reference_images":["data:image/png;base64,..."],"style":"rd_lowpoly__blocky","size":64} -> export {"target":"blockbench"} / {"target":"minecraft"}.

## Canvas edit tools (post-processing; canonical fields use snake_case)
GET /v2/edit/tools -> enabled tool list with balance_cost, credit_cost, is_free, requires_minimum_balance, max_input_size, and api_fields (authoritative; exposed tools may vary). The older "fields" property describes the web canvas UI — API clients should use api_fields.
POST /v2/edit/tools/{tool_id} -> run a tool (holds the connection until done). POST /v2/edit/tools/{tool_id}/estimate -> validate and estimate without running -> {"tool_id", "balance_cost", "credit_cost", "estimate_seconds"}.
ASYNC EDIT TASKS: POST /v2/edit/tools/{tool_id}/tasks (same body) -> 202 {"status": "accepted", "task_id", "request_id", "message"}; poll GET /v2/edit/tasks/{task_id} -> {status: pending|running|succeeded|failed, task_id, created_at, updated_at, result?, error?}. result matches the sync response, and the image is always in output_urls. Use tasks when your HTTP timeout is under ~60 s or for inpainting/outpainting/image_edit (20-40 s). A dropped sync request still runs and is charged. Input and balance errors return 4xx before queuing. On the task endpoint custom_id is an idempotency key: resubmitting the same custom_id returns the original task_id with no second charge.
Every request requires input_image (raw base64 or data:image/...;base64 data URI) and accepts an optional custom_id for correlating runs with your queue (not an idempotency key on the sync run endpoint). Tools: image_edit ($0.18; prompt required, seed?; input <=256px), inpainting ($0.18; mask_image + prompt required, seed?, soft_inpaint?), outpainting ($0.18; expand_left/expand_right/expand_top/expand_bottom with at least one positive, prompt?, seed?, soft_inpaint?), seam_tiling ($0.18; tile_x?, tile_y? — at least one true, seam_width?, repair_window_size?, seed?), background_remover ($0.01; transparency_threshold?, force_solid_pixels?), color_style_transfer ($0.01; extra_input_image required), color_reducer ($0.001; color_count?, dither_mode?, dither_strength?), palette_converter ($0.001; input_palette required, dither_mode?, dither_strength?), k_centroid_downscale ($0.001; width + height required), pixel_correction ($0.001; no extra fields), rotate ($0.001; rotation_degrees?). The $0.001 tools charge animated inputs per frame. Every tool charges before running and auto-refunds on failure; insufficient balance -> 402 not_enough_balance (v1: 400).
Inpainting: POST /v2/edit/tools/inpainting, not /v2/inferences. Use a static input up to 256x256 and a same-size mask. Recommended mask format is RGBA PNG: alpha 0 protects a pixel; alpha >12 selects it for replacement (the visible mask color does not matter). A grayscale mask is also accepted: black protects and values >12 select. Do not send an ordinary fully opaque RGB/RGBA image as the mask because its generated alpha channel selects the whole image. soft_inpaint=false strictly restores pixels outside the selected mask; soft_inpaint=true may accept a bounded transition ring immediately outside it. Output can be in base64_images or output_urls.
dither_mode: none | bayer_2x2 | bayer_4x4 | bayer_8x8; dither_strength 0-10 (0 disables, default 5; values above 10 are treated as the deprecated 0-100 scale and divided by 10). Animated GIF input is supported by color_reducer, palette_converter, color_style_transfer, and k_centroid_downscale only; other tools accept static images.
### Example
POST /v2/edit/tools/background_remover  {"input_image": "<base64>"}
-> {"tool_id": "background_remover", "inference_id": "...", "base64_images": ["<base64>"], "output_urls": [], "balance_cost": 0.01, "credit_cost": null, "charged": true, "remaining_balance": 100.74}
RESULT DELIVERY — DO NOT ASSUME INLINE BASE64: the result arrives in base64_images OR output_urls. image_edit, inpainting, and outpainting normally return base64_images EMPTY and deliver the image only as a hosted URL in output_urls — download it; the other tools return inline base64 (as in the example above). Code that only reads base64_images[0] silently loses those tools' results while still being charged. Always check base64_images first, then fall back to fetching output_urls[0]. Chain tools by feeding the first base64_images item, or a base64-encoded fetched output_urls item, into the next call as input_image. Deprecated camelCase response fields remain available for existing clients; new integrations should read the snake_case fields.
Errors use the canonical v2 envelope {"error":{"code":"...","message":"...","request_id":"..."}}. Preserve X-Request-ID and Retry-After, and branch on code rather than message.

## Pixel Fixer (native-grid reconstruction; $0.002 standard, $0.005 neural)
POST /v2/pixel-fixer/standard {"input_image":"<raw base64 PNG/JPEG/WebP or data URI>"} or {"image_url":"<public HTTPS PNG/JPEG/WebP>"}
POST /v2/pixel-fixer/neural (same image source plus "width"?:positive int,"height"?:positive int)
Provide exactly one of input_image or image_url. Both endpoints return exactly {"base64_images":["<raw base64 PNG>"]}. Standard costs $0.002 per call and Neural $0.005, charged before running and auto-refunded on failure; insufficient balance -> 402 not_enough_balance (v1: 400). Tokens belonging to accounts with a completed purchase receive 120 requests/minute; other tokens receive 10. The allowance is shared across Standard and Neural. Standard uses native Rust grid detection and accepts decoded sources from 16x16 through 16 megapixels. Neural uses neural reconstruction, accepts larger source dimensions, and proportionally bilinear-downscales sources above its 1-megapixel working budget; optional width/height set its target output size, capped at 16 megapixels. Serialized request JSON is limited to 900000 bytes; successful response JSON is limited to 950000 bytes. Public HTTPS URL downloads are limited to 20MB and bypass the ALB request-body limit, but not the response limit. Unknown fields are rejected. Pixel Fixer error codes: not_enough_balance (402; v1: 400), pixel_fixer_request_too_large (413), pixel_fixer_output_too_large (413), invalid_pixel_fixer_image (422), pixel_fixer_rate_limit_exceeded (429), pixel_fixer_failed (500).

## Assistant sessions (beta — conversational generation with plan approval; base /v1/assistant)
Describe the goal in plain language; the assistant picks styles/sizes/settings, proposes a PRICED plan, and only generates after approval. It makes 2D pixel art by default and Low-Poly 3D models only when the message asks for 3D ("3D model", "low poly", "for Blender/Godot/Unity").
Pricing: $0.01 per message (auto-refunded if the turn fails); decisions free; approved plans bill each step at standard rates (3D steps at Low-Poly prices); failed steps auto-refund. 30 messages+decisions/min per key.
POST /sessions -> {id, expires_at} (5 minutes idle; POST /sessions/{id}/keepalive is a free ping). POST /sessions/{id}/messages {message, images?} -> 202 {turn_id}. Poll GET /sessions/{id}/turns/{turn_id} every ~2s; events: message, status, plan, plan_status, image {ref, url, format png|gif}, asset3d {ref, url (render), scene_url, asset_id, version, operation, animations, animation, size, style, cost}, note, error. POST /sessions/{id}/decision {decision: approve|deny, feedback?}.
Plan steps: kind generate|edit|lowpoly; lowpoly steps carry operation generate|revise|animate|split, and animate steps may name an existing animation to change; a split step's prompt is optional and every piece enters the bank as its own 3d ref. 3D models made in the session stay in its bank (format "3d") so later messages can revise, animate or split them.

## Status & errors
GET /v2/status (no auth) -> {"status": {"rd_fast": "ok", "rd_pro": "ok", "rd_plus": "ok", "animations": "ok", "background_removal": "ok"}, "updated_at": 1789681864}. updated_at is Unix seconds. Check before bulk runs.
V1 error shapes (handle all): {"detail": {"code": "inference_failed", "message": "Unable to run inference."}}, {"detail": [{"msg": "Not enough balance."}]}, and {"detail": "Not Found"}.
V2 error shape: {"error":{"code":"inference_failed","message":"Unable to run inference.","request_id":"..."}}. Validation may add safe details.issues. Preserve X-Request-ID and Retry-After. Branch on code, never message.
V1 status compatibility: 400 may mean invalid input or insufficient balance; auth and provider failures also have historical status differences.
V2 status semantics: 400 semantic input; 401 invalid credentials; 402 insufficient balance; 403 permission; 404 concealed/missing; 409 conflict; 413 size; 422 schema; 429 rate limit; 500 unexpected; 502 provider failure; 503 unavailable; 504 timeout.
V2 generation failure codes (on failed tasks too; always refunded): inference_failed (502, generation failed; retry once with identical parameters), provider_busy (503, animation provider overloaded, job rejected before it started; retry after a few minutes — rd_advanced_animation__rotate has no alternate provider so it sees this most), provider_timeout (504, animation took too long and was cancelled; retry), request_timeout (504, execution deadline exceeded; retry).

## Agent best practices
1) Pick a prompt_style from the catalog above (or GET /v2/styles/selector for live limits). 2) POST with "check_cost": true to verify price — free and immediate. 3) Persist an Idempotency-Key, submit once logically, and reuse that key only to recover an uncertain admission of identical inputs. 4) Poll the returned task until succeeded or failed. 5) Reuse the same seed to iterate on a composition; change only the prompt. 6) Base64 images are raw strings — never include a data: URI prefix. 7) Prompts describe the subject; the style handles pixel-art rendering. 8) For a consistent character across images, generate once with RD Pro, then pass that output as reference_images in follow-up requests.
